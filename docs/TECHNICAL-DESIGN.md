# Technical design

TypeScript with Vite, SVG/HTML/CSS, Vitest, local browser hosting. No backend. Separate pure engine from UI; commands validate against authoritative local state and return state/events. UI renders legal actions, not direct mutations. Future server migration is possible, not implemented.

Room templates define normalized node coordinates, internal edges, edge ports; room instances define grid position and quarter-turn rotation. Unique global node IDs link rooms. Use breadth-first search for shortest legal drop distances and reachable connections. Track player position, inventory, relics, statuses, turn owner, decision owner, phase, room deck, token supply, board objects, pending effects and winner. Inject randomness for repeatable tests. Hidden token identities must not appear in rendered UI; local browser storage/devtools are not a security boundary.

Turn state machine: automatic late-phase spawning at turn start, item/move actions, encounter and defensive reactions, victory check, discovery, automatic spawning on room placement, remaining legal item actions, end turn. Each completed placement immediately draws one or two tokens with equal probability; hidden identities use the pre-shuffled supply, and spawn positions are uniformly sampled without replacement from all existing unoccupied board nodes. Exclude player positions and tokens, cap by supply and eligible nodes, and inject randomness for repeatable tests. After expansion finishes, subsequent turn starts spawn one token automatically. No manual token-placement phase or board targeting is required. Pause on pending player decisions. Resolve forced steps individually. Possession creates an immediate pending displacement with affected player, left-hand decision owner and four-step budget, using breadth-first search to highlight all reachable destinations (excluding the origin and occupied nodes). One click executes a shortest route, ties resolved in stable board-link order, without inspecting hidden token identities. Blade remains step-by-step. End turn and normal actions remain blocked until completion; each step resolves encounters, and a new trap interrupts the displacement. No discovery from forced movement. No delayed Possession status. Phase 7: winner is a nullable player ID. Check settled encounters before discovery and after every forced step; stop movement and reject subsequent actions on victory. Theft can also qualify a player already on Exit. Save a versioned snapshot plus the latest 200 action log entries to one localStorage slot after refresh/state changes. Rebuild board graph from canonical room templates, validate room/card counts, token conservation and identities, occupancy, turn order, pending effects and winner on load. Persist game decisions but reset camera, UI selections and informational encounter dialogs on resume. Handle blocked storage and malformed/incompatible saves without crashing. Storage is scoped to the browser profile and origin. No offline reload guarantee until offline caching is implemented.

Test component counts, graph rotation/alignment, occupancy, one-step movement, turn progression, token secrecy, drop priorities, reaction chains and victory. Tests and builds run manually on the player's local machine. No GitHub Actions or Pages.

Board input (v0.6.4): nearest-center hit testing uses screen-space coordinates, minimum 16 CSS pixel radius, and preserves larger existing hit areas when zoomed in. Overlapping targets choose the closest center, including invalid spots (engine legality remains authoritative). Pan suppression and keyboard selection remain intact.
